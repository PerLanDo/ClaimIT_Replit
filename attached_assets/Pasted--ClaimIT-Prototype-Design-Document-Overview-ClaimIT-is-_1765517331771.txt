# ClaimIT Prototype - Design Document

## Overview

ClaimIT is a Progressive Web Application (PWA) for campus lost and found management at MSU-IIT. The prototype demonstrates core functionality including item reporting, searching, claims management, messaging, and administrative features. Built with React.js frontend and Firebase backend, the system supports dual-mode item recovery (peer-to-peer and centralized SID management).

### Key Design Goals

- **Accessibility**: 24/7 availability via web browser on any device
- **Security**: Role-based access control with SSO authentication
- **Scalability**: Firebase backend with path to SQL migration
- **Usability**: Mobile-first responsive design
- **Transparency**: Complete audit trail and real-time notifications

## Correctness Properties

_A property is a characteristic or behavior that should hold true across all valid executions of a system-essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees._

### Property 1: Role Assignment Consistency

_For any_ user authentication, the assigned role SHALL match the user's account type from the authentication provider.
**Validates: Requirements 1.2**

### Property 2: Item Creation Integrity

_For any_ valid item report submission, the created item record SHALL contain all required fields (title, category, description, location, date) and have the correct status ("Lost" or "Found").
**Validates: Requirements 2.1, 2.2**

### Property 3: Photo Upload Validation

_For any_ photo upload attempt, ClaimIT SHALL accept only files that are JPEG or PNG format AND under 5MB in size AND the total count does not exceed 5.
**Validates: Requirements 2.3**

### Property 4: QR Code Uniqueness

_For any_ successfully submitted item, the generated QR code SHALL be unique across all items in the system.
**Validates: Requirements 2.5**

### Property 5: Form Validation Completeness

_For any_ item report with empty required fields, the submission SHALL be rejected with appropriate validation errors.
**Validates: Requirements 2.6**

### Property 6: Search Result Accuracy

_For any_ search query, all returned items SHALL contain the search keywords in either the title or description field.
**Validates: Requirements 3.2**

### Property 7: Filter Result Correctness

_For any_ applied filter combination, all returned items SHALL match ALL specified filter criteria (category, status, date range, location).
**Validates: Requirements 3.3**

### Property 8: Claim Proof Minimum Length

_For any_ claim submission, the proof of ownership description SHALL have at least 50 characters.
**Validates: Requirements 4.1**

### Property 9: Claim Status Transition

_For any_ valid claim submission, the associated item status SHALL change to "Pending_Claim".
**Validates: Requirements 4.2**

### Property 10: Self-Claim Prevention

_For any_ claim attempt where the claimant is the item reporter, the claim SHALL be rejected.
**Validates: Requirements 4.6**

### Property 11: Message Chronological Order

_For any_ conversation view, messages SHALL be displayed in chronological order by timestamp.
**Validates: Requirements 5.4**

### Property 12: Handover QR Validation

_For any_ QR code scan during handover, the system SHALL correctly validate whether the code matches the approved claim.
**Validates: Requirements 7.2**

### Property 13: Handover Completion State

_For any_ valid QR code scan, the item status SHALL change to "Returned" and both users' transaction histories SHALL be updated.
**Validates: Requirements 7.3**

### Property 14: Reputation Score Increment

_For any_ successful item return, the finder's reputation score SHALL increase by the defined increment value.
**Validates: Requirements 8.3**

### Property 15: Item Serialization Round-Trip

_For any_ valid Item object, serializing to JSON and deserializing back SHALL produce an equivalent Item object.
**Validates: Requirements 10.1, 10.2**

### Property 16: User Serialization Round-Trip

_For any_ valid User object, serializing to JSON and deserializing back SHALL produce an equivalent User object.
**Validates: Requirements 10.3, 10.4**

### Property 17: Claim Serialization Round-Trip

_For any_ valid Claim object, serializing to JSON and deserializing back SHALL produce an equivalent Claim object.
**Validates: Requirements 10.5, 10.6**

## Error Handling

### Client-Side Errors

| Error Type | Handling Strategy |
| --- | --- |
| Network failure | Auto-save to localStorage, retry with exponential backoff |
| Validation errors | Inline field highlighting with specific error messages |
| Auth expiration | Redirect to login with return URL preservation |
| File upload failure | Display error, allow retry, suggest file size reduction |

### Server-Side Errors

| Error Type | Handling Strategy |
| --- | --- |
| Database write failure | Return error to client, log for admin review |
| Storage quota exceeded | Notify admin, reject upload with user message |
| Rate limiting | Return 429 with retry-after header |
| Invalid data | Return 400 with validation details |

### Error Response Format

```typescript
interface ErrorResponse {
  code: string;
  message: string;
  details?: Record<string, string>;
  timestamp: Date;
}
```

## Testing Strategy

### Dual Testing Approach

The ClaimIT prototype employs both unit testing and property-based testing to ensure comprehensive coverage:

1. **Unit Tests** - Verify specific examples, edge cases, and integration points
2. **Property-Based Tests** - Verify universal properties that should hold across all inputs

### Testing Framework

- **Test Runner**: Vitest
- **Property-Based Testing**: fast-check
- **Component Testing**: React Testing Library
- **Minimum Iterations**: 100 runs per property test

### Unit Testing Focus Areas

- Component rendering and user interactions
- Form validation logic
- Authentication flow
- API service functions
- Utility functions (date formatting, QR generation)

### Property-Based Testing Focus Areas

Each property-based test MUST be tagged with the format:
`**Feature: claimit-prototype, Property {number}: {property_text}**`

Properties to implement:

1. Role assignment consistency
2. Item creation integrity
3. Photo upload validation
4. QR code uniqueness
5. Form validation completeness
6. Search result accuracy
7. Filter result correctness
8. Claim proof minimum length
9. Claim status transition
10. Self-claim prevention
11. Message chronological order
12. Handover QR validation
13. Handover completion state
14. Reputation score increment
15. Item serialization round-trip
16. User serialization round-trip
17. Claim serialization round-trip
